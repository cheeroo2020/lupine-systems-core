Scene 02 · The seven lenses

One payment, seven graphs

A graph is just a network — nodes connected by edges, each edge carrying a weight. Aiva keeps seven of them, each describing the same payment from a different angle.

Hop Which banks can physically reach which banks. edges: latency + reliability
Corridor FX routes — AUD→SGD→EUR vs AUD→USD→EUR. edges: depth, volatility, spread
Liquidity Treasury depth at each tier. Anticipates droughts. edges: pool capacity
Volatility Price-risk propagation across the path. edges: σ per hop
Compliance Which regulatory regimes are compatible. edges: flag probability
Failure Cascading risk, modelled with Bayesian updating. edges: P(failure)
Medical urgency Biological payload timing. Phase 2 — not in V0. out of scope

Six graphs in the V0 lineage. The seventh is a future direction.

Scene 03 · Why graphs at all

Because a payment has options

A graph is the right shape because the question is genuinely a path question: many possible routes, each a sequence of hops, each hop carrying cost.

Legacy systems don't have a graph. They have a list — the correspondents this bank happens to have agreements with. One option, pre-chosen, years ago.

You cannot optimise over a set you never enumerated.

Same corridor, different lensessame nodes, different weights

AU ─── C1 ─── C2 ─── SG hop graph   → 4h · 11h · 5h liquidity    → deep · deep · thin volatility   → low · low · high compliance  → clean · clean · flag risk

One physical path. Four completely different pictures of it — and the last hop looks fine on three of them.

Scene 05 · The correction

What you said in April

Comprehension check · P2-Ch113 Apr 2026

"In sequential evaluation, it is time consuming, and by removing this sequential evaluation, we can choose constraints based on faster outputs."

You reached for speed. Reasonable — and it's what almost everyone says.

But speed is a side effect. The real cost of sequential evaluation is that a constraint checked first can terminate the payment before any other constraint gets a chance to route around it.

Simultaneous evaluation doesn't just answer faster.
It finds answers sequential never reaches.

Scene 07 · Mechanism #5

Deterministic

Identical payment · sent three times · one hour apart

Legacy correspondent banking

run 1AU → USD hub → SG · 31h
run 2AU → SGD direct → SG · 6h
run 3AU → USD → HKD → SG · 74h

Three paths. Nobody chose them. Nobody can reconstruct why.

Aiva

run 1AU → SGD direct → SG · 0.84
run 2AU → SGD direct → SG · 0.84
run 3AU → SGD direct → SG · 0.84

Same inputs, same output. Every time — and the reasoning is recorded.

Deterministic means: given the same inputs, you get the same output. No randomness, no human judgment inserted mid-flow. The outcome is computed — and knowable before the money moves.

Scene 08 · The handoff

The execution blueprint

Aiva's output isn't "use route B." It's a complete, deterministic instruction set handed down to Rail — which executes it exactly as specified, adding no judgment of its own.

Optimal corridor path

The fallback tree matters most. It's why Rail can correct forward when a hop fails — the alternate was computed before the payment ever moved. That's Lesson 8.

Naming the gap precisely reads as competence. Vagueness reads as not understanding your own system.

Scene 10 · The thesis

Computed, not guessed

Legacy routing

  • A list of pre-agreed correspondents
  • Constraints checked one at a time
  • First rejection ends the payment
  • Two identical payments, two paths
  • No record of what was considered

Aiva

  • Seven graphs over every viable path
  • All constraints weighed simultaneously
  • Rejection on one axis triggers a re-route
  • Same inputs, same route, every time
  • A blueprint plus an evidence anchor map
"Legacy routing checks constraints one at a time, so a compliance flag kills a payment that a different corridor would have sailed through. Aiva evaluates seven dimensions simultaneously and outputs a deterministic blueprint — same inputs, same route, every time, knowable before the money moves."

Scene 11 · Check yourself

Say these out loud

Both of today's questions are on your list of twelve. Neither came out right in April.

Why is simultaneous evaluation better than sequential?Mechanism #3

Not because it's faster — because it produces better decisions. In a sequential engine, a constraint checked first can terminate the payment before the routing engine ever runs, so the corridor where that flag never fires is never discovered. Each system decides in isolation, blind to the others. Aiva evaluates all seven at once and can find paths sequential systems structurally cannot reach.

Define "deterministic" in one sentence.Mechanism #5

Given the same inputs, you get the same output — every time, with no randomness and no human judgment in the middle. Legacy systems are non-deterministic: two identical payments an hour apart can take different paths for reasons nobody can afterwards reconstruct. Note this is a separate idea from simultaneous evaluation — that's how Aiva computes; determinism is a property of the result.

What does Aiva hand to Rail, and which part matters most?

An execution blueprint: corridor path, hop-level timing model, liquidity requirements, compliance probability matrix, FX exposure curve, fallback tree, and the evidence anchor map for Cloked. The fallback tree is the critical one — it's what lets Rail correct forward instead of rolling back when a hop fails.
