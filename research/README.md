# Research

Notes that feed product discovery: what has been read, what problems have been observed,
and what engineers have said they need. The aim is to find a specific user with a recurring
problem that current approaches handle poorly, before building anything for it.

**No notes yet.** Industry conversations are planned to begin within the first three months
(by January 2027).

---

## Three kinds of note

| Kind | Prefix | Holds |
|---|---|---|
| Reading note | `R` | What a named source says, with link and date read |
| Problem observation | `P` | A failure or gap seen or reported, with how we know |
| Conversation summary | `C` | What an engineer or operator said about their work and problems |

File name: `research/YYYY-MM-DD-R-short-title.md` (or `-P-` / `-C-`). Copy `TEMPLATE.md`.

## Rules

1. **Separate what the source says from what we think it means.** The template has a
   section for each.
2. **Every factual claim names its source and the date it was read.** It stays
   **[ASSUMED]** until checked against a second source.
3. **The repository is public.** Conversation summaries need the person's consent, and
   record the scope of that consent. Without permission, no names, no employer, no contact
   details, and nothing confidential. Describe a role instead ("protection engineer at a
   network operator").
4. **Existing solutions are research, not a threat.** Record what already exists and why
   people use it, so we can see where a contribution might fit.
5. **Free sources first.** Note any paywall rather than working around it.
